## New experience

Warm stone, deep green/ink and bronze styling; responsive owner workspace; searchable/sortable customer directory; safe CSV export; actionable overview; ZIP map with revenue, outstanding-balance and customer-count shading; territory/customer drilldowns; preserved PDF import checks and payment/void workflow; monthly report print/PDF support; clearer source coverage and data quality.

The map uses bundled NYC ZCTA geometry and Leaflet 1.9.4, with no third-party basemap. Polygons and ZIP buttons are keyboard accessible. Areas outside the geometry set stay visible in the ZIP list.

## Outstanding items

1. **Compromised-password protection is disabled in Supabase Auth.** Enable it if supported by the current plan. See [Supabase password security](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). This account-level setting is not exposed by the connected database tools.
2. Review the pre-snapshot historical payment flagged in the live database. Verify against Zoho before deciding whether to void it. No financial history was silently changed.
3. Loaded wholesale, product and festival sales each span a multi-month block. Genuine monthly comparisons require separate monthly exports or transaction-level ingestion. Replacing historical blocks requires a designed, reconciled replacement procedure; importing overlapping monthly reports is intentionally blocked.
4. Direct API synchronization is not connected. It requires identifying the exact Zoho product/account and connecting Zoho and Square credentials securely. Do not put OAuth refresh tokens or webhook secrets in this frontend.
5. Set GitHub Pages publishing source to GitHub Actions before merging the new build workflow. Existing production frontend remains until deployed; database hardening is already live.
6. Test the owner workflows with representative real reports on an actual phone, including PDF formats with refunds, credits, wrapped names and encrypted/scanned reports. Unrecognized/mismatched reports fail closed, but synthetic fixtures cannot certify every export variant. Scanned image PDFs are not OCR-processed.
7. MFA for the two owners, backup/restore drills, monitoring, and owner enrollment/removal need account-level operational setup. Avoid replacing the owner allowlist with “all signed-in users.”

## Recommended roadmap

**First: reliable transaction-level sync.** Use a server-side Supabase integration that pulls invoices, payments, credits and customer records from the exact Zoho product, and orders, payments, refunds and catalog data from Square. Start with read-only scopes, historical backfill and daily reconciliation; add signed webhook ingestion and periodic repair polling. Use stable external IDs and idempotent upserts so retries do not duplicate revenue. Keep PDFs as a reconciliation fallback. [Zoho Books OAuth](https://www.zoho.com/books/api/v3/oauth/) and [webhooks](https://www.zoho.com/books/api/v3/webhooks/); [Square OAuth](https://developer.squareup.com/docs/oauth-api/overview) and [payment webhooks](https://developer.squareup.com/docs/payments-api/webhooks).

**Next: distribution decisions.** Invoice due dates unlock actual overdue aging. Last order dates unlock reorder prompts. Product purchase/landed cost, spoilage and delivery cost unlock contribution margin. Stock on hand and lead times unlock purchasing suggestions. The current reports cannot substantiate these metrics, so they should not be fabricated from sales totals.

**Then: field operations.** Add customer contact/address editing with audit history, route-day planning, visit notes, photo attachments, delivery checklists and online payment shortcuts. A phone home-screen app is feasible. Offline writes need an explicit queue, unique operation IDs and conflict resolution before money-related updates can be safe.

**Presentation readiness.** Add a reconciled monthly owner/bank pack with date coverage, sales basis, gross margin, cash collected, receivables aging, customer concentration and source traceability. Styling improves presentation; reconciled data and documented definitions make the numbers defensible.
